# 🚀 Wemo Ops Center v5.3.1

**Release Title:** v5.3.1 - Fast, Reliable Discovery & New Builds for Every Platform
**Tag:** `v5.3.1`

## 🌟 What's New in v5.3.1

This release fixes slow and incomplete device discovery, fixes the macOS "damaged app" error and the Linux GUI crash on Fedora, and adds builds for Raspberry Pi, ARM Linux and macOS Tahoe.

### 📡 Faster, Complete Device Discovery

* **Much faster deep scans** ([#25](https://github.com/qrussell/wemo-ops-center/issues/25)): computers with ports 49152–49155 open (most Windows PCs) used to stall the scan for up to 40 seconds each. They are now rejected in seconds. In testing:
  * a network with three such PCs: **49.8 s → 7.9 s**
  * a /23 network with 7 Wemo devices: **42.7 s → 13.6 s**
* **Every device is found** ([#24](https://github.com/qrussell/wemo-ops-center/issues/24)): devices are now tracked by their unique ID instead of their name, so several devices with the same name (e.g. three un-renamed "Wemo Mini") no longer collapse into one. They are shown as `Wemo Mini (1122)`, `Wemo Mini (3344)` (last 4 characters of the MAC address).
* **All your networks, automatically** ([#30](https://github.com/qrussell/wemo-ops-center/issues/30)): the app now scans every network your computer is connected to (e.g. Ethernet *and* an IoT Wi-Fi), plus your saved subnets, with the selected subnet first. Connected networks appear in the network list on their own. VPN, virtual machine and container adapters are skipped.
* **Devices appear sooner:** broadcast (SSDP) results show right away; the deep scan adds anything it missed.
* **Reliable on busy networks:** the scan now sweeps for open ports first and then checks only the devices that answered. Devices found in the previous scan are re-checked first, so they don't drop off the list.
* **Newly provisioned devices are picked up automatically:** the app rescans 60 and 120 seconds after a successful "Push Configuration".

### ⚙️ Background Service & Mobile Web App

* **Connected networks scanned at startup and on Scan.** Every 5 minutes, only saved subnets are deep-scanned (as before), so the service doesn't constantly probe your network.
* **New setting:** *Deep-scan all connected networks every 5 min* (off by default), in the desktop **Settings** tab and the web app's Settings.
* **Web app Settings** now lists auto-detected connected networks next to your saved subnets.
* **Fixed:** after any failed scan, the service stopped scanning until it was restarted.
* **Fixed:** settings changed in the web app (subnets, the new switch) could be undone the next time the desktop app saved its own settings, and vice versa.

### ⬆️ Update Button

* Only offers a version that is **newer** than the one you are running (previously it offered any different version, including older ones).
* Ignores drafts, pre-releases and MCP server releases.

### 🐧 Linux

* **Fixed a GUI crash on Fedora** (`X Error BadLength … RenderAddGlyphs`) when a color emoji font is installed, and 45 fontconfig warnings on Fedora 45. The app now uses your distribution's own X11 and font libraries, which are installed automatically as package dependencies.
* **Fixed missing status icons** ([#2](https://github.com/qrussell/wemo-ops-center/issues/2)): status labels use symbols every font has (`● RUNNING`, `▲ STOPPED`, `↓ Update`) instead of emoji.
* **New:** `.deb` for **arm64** (Raspberry Pi 4/5, Raspberry Pi OS 64-bit) and `.rpm` for **aarch64**.
* Packages no longer pull in an unused system Python and Tk.
* Tested on Rocky Linux 9, Fedora 40 and 45, Ubuntu 22.04 and 24.04, and Debian 13.

### 🍎 macOS

* **Fixed "WemoOps is damaged and can't be opened"** ([#21](https://github.com/qrussell/wemo-ops-center/issues/21)): the app bundle is now re-signed after the background service is added to it.
* **Builds for macOS 15 and macOS 26 Tahoe**, each for Apple Silicon and Intel. Pick the DMG matching your macOS version and chip.
* The build now checks that its Python has working Tk, so a DMG that can't launch is never produced.

### 🐳 Docker

* The `ghcr.io/qrussell/wemo-ops-server` image is now built for **amd64 and arm64** (Raspberry Pi) and published with each release, so it always matches the desktop and server code.
* The image requires a **Linux host with `network_mode: host`** (Raspberry Pi, NAS, VM, server). Docker Desktop on Windows/macOS routes container traffic through its own proxy and misses devices; use the desktop app there.

### 🛠️ Under the Hood

* Raised the open-file limit on macOS and Linux so large scans can't silently fail.
* Repeated **Scan** clicks no longer start parallel scans.
* New automated release pipeline: every package is built on clean GitHub-hosted runners, with `SHA256SUMS.txt` for verifying downloads.

## ⚠️ Upgrade Notes

* **Devices sharing a name** now show a short suffix, e.g. `Wemo Mini (1122)`. Rename them in the Dashboard to drop it.
* **Schedules for a shared name:** an existing schedule for "Wemo Mini" now runs on *all* devices named "Wemo Mini" (previously it controlled one of them at random). To target one device, recreate the schedule using its new name.
* **macOS DMG names changed:** use `macos15` for macOS 15 (Sequoia) and `macos26` for macOS 26 (Tahoe), `apple-silicon` for M-series Macs and `intel` for Intel Macs.
* **Linux packages** now depend on the system's X11/font libraries (installed automatically) instead of `python3` / `python3-tkinter`.

## 🧭 Known Issues

* **Windows SmartScreen** shows "Windows protected your PC" on first launch: click **More info → Run anyway**.
* **macOS** may ask for confirmation the first time: right-click (or Control-click) **WemoOps** → **Open**.
* **Docker Desktop** (Windows/macOS) can't reliably discover devices; run the container on a Linux host.
* **Dimmer minimum/maximum brightness** settings are not supported yet.
