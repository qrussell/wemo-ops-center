# 🚀 Wemo Ops Center v5.4.0

**Release Title:** v5.4.0 - Remote Server, Insight Power Readings & a Better Windows Installer
**Tag:** `v5.4.0`

## 🌟 What's New in v5.4.0

This release lets the desktop app work with a Wemo Ops Server on another machine, shows power readings for Insight plugs, and fixes Windows installs that were blocked by security policies or kept phones from opening the mobile web app.

### 🖥️ Use a Remote Wemo Ops Server

* **Point the desktop app at your server** ([#22](https://github.com/qrussell/wemo-ops-center/issues/22)): if you run Wemo Ops Server on a Raspberry Pi, NAS, Linux server or in Docker, go to **Settings → Background Service**, turn off *Use the background service on this computer*, enter the server's address (e.g. `homelab.local:5050`) and click **Save & Test**.
* With a remote server, the sidebar shows **CONNECTED** / **UNREACHABLE** instead of offering to start the local service. Schedules, **Scan** and settings go to that server, and the **Mobile App** QR code points to it.
* Addresses without `http://` or a port get `http://` and `:5050` added. The `WEMO_OPS_SERVER_URL` environment variable overrides the setting.
* **Keep the server on your home network.** It has no login, so don't port-forward port 5050 to the internet.

### ⚡ Insight Power Readings

* **Insight plugs show their power use** ([#27](https://github.com/qrussell/wemo-ops-center/issues/27)): the current draw in watts and today's energy in kWh, on the desktop Dashboard and in the mobile web app. Readings update with the device status, without extra network traffic.
* For developers: `/api/devices` adds `power_w` and `today_kwh` for Insight devices.

### 🪟 Windows Installer

* **Installs to Program Files** ([#29](https://github.com/qrussell/wemo-ops-center/issues/29)): the installer now asks for administrator rights and installs to `C:\Program Files\WemoOps`, so security tools and group policies that block programs in the user profile (e.g. CryptoPrevent) no longer stop the background service. You can choose another folder, or *install for me only*.
* **Upgrading from 5.3.1 or earlier** removes the old copy in `%APPDATA%\WemoOps` first. Your settings, schedules and Wi-Fi profiles in that folder are kept.
* **Phones can open the mobile web app** ([#26](https://github.com/qrussell/wemo-ops-center/issues/26)): a new installer option (on by default) adds a Windows Firewall rule that lets devices on your home network reach the background service. It applies to *Private* networks; if Windows marks your network as *Public*, change it to *Private* in Windows Settings. Uninstalling removes the rule.
* The Dashboard now starts as your own user after installation, not as administrator.

### 🔍 Display

* **175% and 200% UI scaling** ([#2](https://github.com/qrussell/wemo-ops-center/issues/2)) in **Settings → UI Scaling**, for high-resolution screens such as a Pixelbook on Linux.

### 🧪 Tested

* Windows 11: upgrade from a per-user install to Program Files, with settings kept in `%APPDATA%\WemoOps`; installer script compiled with Inno Setup 6.
* Windows 11 (from source): remote server set and tested against a second Wemo Ops Server, 200% scaling, discovery of 7 devices on a separate subnet.
* Linux (Ubuntu 24.04 under Xvfb): Settings → Background Service, remote server connected/unreachable states, Insight power readings on the Dashboard and in the web app with a simulated Insight plug.

## ⚠️ Upgrade Notes

* **Windows:** the installer now needs administrator rights (or choose *install for me only*). After upgrading, the app runs from `C:\Program Files\WemoOps`; your data stays in `%APPDATA%\WemoOps`.
* **Microsoft Defender** may report `Trojan:Win32/Bearfoos.A!ml` for the unsigned app. This is a false positive from Defender's machine-learning model and has been reported to Microsoft ([#33](https://github.com/qrussell/wemo-ops-center/issues/33)). Verify your download with `SHA256SUMS.txt`.

## 🧭 Known Issues

* **Insight power readings** were tested with a simulated Insight plug only. If yours shows wrong numbers, please open an issue.
* **Windows SmartScreen** shows "Windows protected your PC" on first launch: click **More info → Run anyway**.
* **macOS** may ask for confirmation the first time: right-click (or Control-click) **WemoOps** → **Open**.
* **Docker Desktop** (Windows/macOS) can't reliably discover devices; run the container on a Linux host.
* **Dimmer minimum/maximum brightness** settings are not supported yet.
