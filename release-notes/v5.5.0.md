# 🚀 Wemo Ops Center v5.5.0

**Release Title:** v5.5.0 - Device Clock Sync, a Cleaner Windows Build & a Homebridge Installer That Doesn't Hang
**Tag:** `v5.5.0`

## 🌟 What's New in v5.5.0

This release keeps your Wemo devices' own clocks right, changes how the Windows app is built so Microsoft Defender stops flagging it, and fixes the Homebridge installer hanging.

### 🕒 Device Clock Sync

* **Set your devices' clocks** ([#32](https://github.com/qrussell/wemo-ops-center/issues/32)). Wemo plugs keep their own clock for schedules and away mode stored on the device (for example, made in the old Wemo app). If that clock is wrong, those schedules fire at the wrong time. Wemo Ops Center now sets each device's clock and time zone, including daylight saving time, from your computer or server.
* **Desktop app:** in **Maintenance**, pick a device in the new **Device** list and click **Sync Selected Device**, or click **Sync All Devices**.
* **Daily sync:** turn on **Settings → Keep device clocks in sync (daily)** (off by default) and the background service or Wemo Ops Server does it once a day.
* **Mobile web app:** **Setup → Sync Clocks Now** syncs every device, and the same daily option is there too.
* Wemo devices can't report their clock back, so the app can't show the device's current time. Check the result with a schedule stored on the device.
* For developers: `POST /api/sync_clocks` syncs every device and returns the names synced and failed.

### 🛠️ Maintenance

* The device list at the top of **Maintenance** now has a **Device** label and applies to every button on the page.
* If no Wemo devices have been found yet, the buttons now say so, or say that a scan is still running, and tell you what to check. Before, they showed "Device not found".

### 🪟 Windows Build

* **No more Defender false positive** ([#33](https://github.com/qrussell/wemo-ops-center/issues/33)). The app, the background service and the Homebridge helper used to be single self-extracting `.exe` files, a pattern Microsoft Defender's machine-learning check flagged as `Trojan:Win32/Bearfoos.A!ml`. They are now built as one folder of regular files. A Defender scan of the installed app comes back clean.
* Nothing changes for you: the installer still installs to `C:\Program Files\WemoOps`, upgrades a 5.4.0 install in place, and keeps your data in `%APPDATA%\WemoOps`.

### 🏠 Homebridge Installer

* **No longer hangs at "Starting Homebridge Service"** ([#31](https://github.com/qrussell/wemo-ops-center/issues/31)). If the Homebridge service doesn't start within 3 minutes, the installer stops waiting and shows how to check its log (`sudo hb-service logs`), the common causes (port 8581 in use, Node.js older than 20) and the command to run yourself.
* It finds `hb-service` even when it isn't on `sudo`'s PATH, and doesn't run `sudo` twice when it is already running as administrator.

### 🧪 Tested

* Windows 11: test installer installed over 5.4.0, Dashboard, background service and mobile web app QR code working, Defender scan of `C:\Program Files\WemoOps` with 0 threats.
* Real Wemo plugs: clock sync from the desktop app.
* Ubuntu 24.04 with systemd (Docker): Homebridge install succeeds; with no systemd, port 8581 taken, or `hb-service` outside `sudo`'s PATH it ends with a message; a service start that never returns now stops after 3 minutes instead of hanging.
* Linux (Ubuntu 24.04 under Xvfb): Maintenance and Settings in the desktop app, `/api/sync_clocks` and the web app's Sync Clocks Now with simulated devices.

---

## ⚠️ Upgrade Notes

* **Windows:** install over your current version as usual. The installed app is now a `WemoOps` folder with `WemoOps.exe`, `wemo_service.exe` and an `_internal` folder.
* **Device clock sync is off by default.** Turn it on in Settings (desktop app or web app) if you use schedules stored on the devices.

## 🧭 Known Issues

* **Insight power readings** were tested with a simulated Insight plug only. If yours shows wrong numbers, please open an issue.
* **Windows SmartScreen** shows "Windows protected your PC" on first launch: click **More info → Run anyway**.
* **macOS** may ask for confirmation the first time: right-click (or Control-click) **WemoOps** → **Open**.
* **Docker Desktop** (Windows/macOS) can't reliably discover devices; run the container on a Linux host.
* **Mobile web app:** on a server with no rules yet, the Rules page shows an empty list instead of "No active rules".
* **Dimmer minimum/maximum brightness** settings are not supported yet.
