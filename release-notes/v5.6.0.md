# 🚀 Wemo Ops Center v5.6.0

**Release Title:** v5.6.0 - Schedules Stored on the Plug (Experimental)
**Tag:** `v5.6.0`

## 🌟 What's New in v5.6.0

This release adds experimental schedules stored on the Wemo plug itself, next to the schedules Wemo Ops runs, and keeps the two clearly apart.

### 🗓️ Two Kinds of Schedule in Automation

* **Automation now has two tabs** ([#28](https://github.com/qrussell/wemo-ops-center/issues/28)), one for each place a schedule can run. Every schedule is labelled with where it runs: **WEMO OPS** or **PLUG**.
* **Run by Wemo Ops** is the scheduler you already know. Wemo Ops runs these on your computer (background service) or your Wemo Ops Server, so that computer or server must stay on. It works on every Wemo device and supports sunrise/sunset. Your existing schedules are here, unchanged.
* **Stored on Device (experimental)** shows the rules saved on a plug, including ones made in the old Wemo app. You can:
  * add an ON time, an OFF time or both, on the days you choose (**Save to Device**)
  * turn a rule off or on, delete a rule Wemo Ops made, or **Clear All**
  * **Restore Backup** to put back an earlier set of rules

### 🔁 Move Schedules Between the Plug and Wemo Ops

* **Push to Device** (on a Wemo Ops schedule) stores a fixed-time Turn ON or Turn OFF schedule on the plug.
* **Copy to Wemo Ops** (on a plug rule) has Wemo Ops run it instead, including sunrise/sunset rules. Use it for plugs whose firmware no longer runs its own schedules.
* After pushing or copying, the app asks whether to turn off the original, so a schedule doesn't run in both places.

### 🛡️ Safety

Writing to a plug's rules is the risky part, so the app:
* backs up the plug's current rules before every change, to `rules-backups` in the app data folder (`%APPDATA%\WemoOps` on Windows)
* won't write if it can't download the plug's existing rules (it would otherwise start from an empty set and erase them)
* won't write if the rules changed since it read them (for example, another app changed them)
* reads the rules back after each save, and changes one device at a time
* only lets you delete rules Wemo Ops made one by one (Clear All removes everything, after asking)
* syncs the plug's clock before saving

## ⚠️ Known Limitation: Plugs May Not Run These Schedules

Plugs accept and keep these schedules, but since Belkin's cloud shut down some firmware never runs them. On a Wemo Mini with firmware 2.00.11565, schedules saved by this version did not switch the plug, in several tests including after a power cycle. One pywemo user reports an F7C027 on firmware 2.00.11851 running them.

That's why the tab is marked experimental. **Watch the plug the first time a schedule is due.** If it doesn't switch, use **Copy to Wemo Ops** and let Wemo Ops run it. If schedules stored on your plug do work, please comment on [#28](https://github.com/qrussell/wemo-ops-center/issues/28) with your plug model and firmware version.

### 🧪 Tested

* Windows 11, real Wemo Mini (firmware 2.00.11565): both Automation tabs, reading the plug's rules and saving a schedule to the plug work; the saved schedule did not switch the plug (see above).
* Rules logic against a simulated plug: add, delete, clear, restore, duplicate names, a failed download with an existing rules file, and a change by another app between read and write.
* Desktop app rendered with simulated devices on Linux (Python 3.12) and Windows 11 (screenshots in the README).

---

## ⚠️ Upgrade Notes

* Nothing changes for existing schedules: they are on the **Run by Wemo Ops** tab and keep running as before.
* The mobile web app and Wemo Ops Server are unchanged in this release; schedules stored on the plug are managed from the desktop app.

## 🧭 Known Issues

* **Schedules stored on the plug** may be kept but never run, depending on firmware (see above).
* **Insight power readings** were tested with a simulated Insight plug only. If yours shows wrong numbers, please open an issue.
* **Windows SmartScreen** shows "Windows protected your PC" on first launch: click **More info → Run anyway**.
* **macOS** may ask for confirmation the first time: right-click (or Control-click) **WemoOps** → **Open**.
* **Docker Desktop** (Windows/macOS) can't reliably discover devices; run the container on a Linux host.
* **Mobile web app:** on a server with no rules yet, the Rules page shows an empty list instead of "No active rules".
* **Dimmer minimum/maximum brightness** settings are not supported yet.
